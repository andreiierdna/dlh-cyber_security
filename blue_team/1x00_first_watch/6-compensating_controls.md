# Task: The Legacy Dilemma — MRI Compensating Control Strategy

## Risk Analysis

The MRI workstation represents a **critical enterprise security risk** because Windows XP Embedded has been unsupported since April 2014, meaning newly discovered vulnerabilities cannot be remediated through normal security patching and known weaknesses may remain permanently exploitable. The risk extends beyond Radiology because MedDefense Central operates a flat 10.10.0.0/16 network in which workstations, servers, and medical devices share the same broadcast domain, so a compromise of the MRI workstation could provide an attacker with a foothold for lateral movement toward systems such as PACS, EHR, Active Directory, and other connected medical devices.  The MRI is particularly significant because it must communicate with PACS, which contains PHI, while the broader medical-device environment includes patient monitors and infusion pumps that are also reachable through the inadequately segmented network.  Windows XP's obsolete security architecture and exposure to legacy protocol vulnerabilities make this network proximity substantially more dangerous because the organization cannot rely on current operating-system protections to prevent exploitation or lateral movement.

## Implementation Priority

If MedDefense can implement only **one control immediately, the dedicated MRI VLAN with default-deny ACLs should receive the highest priority**.

This control provides the greatest risk reduction because the most consequential aspect of the current condition is not simply that the MRI runs Windows XP; it is that an unpatchable Windows XP medical device is directly connected to MedDefense Central's flat network. The environment documentation confirms that ordinary workstations, servers, and medical devices currently share the same broadcast domain, while critical systems include PACS, EHR infrastructure, Active Directory, patient monitors, and infusion pumps.  A successful compromise can therefore become an enterprise incident rather than remaining confined to one imaging workstation.

Network segmentation directly breaks that attack path. The MRI can remain operational and continue transmitting approximately 45 daily studies to PACS, while a default-deny policy permits only the minimum communications required for that clinical function. Unlike antivirus installation, OS hardening, patching, or upgrading, segmentation does **not modify the manufacturer's certified Windows XP configuration**. It therefore addresses the largest source of systemic exposure while respecting the four stated constraints: the device is not patched, upgraded, replaced, or disconnected.

Residual risk remains because the Windows XP workstation itself is still vulnerable and its required connection to PACS cannot be eliminated. For that reason, segmentation should be treated as the **first and highest-value containment measure**, followed by network monitoring/IPS, formal exception management, and physical-access restrictions as resources become available.
